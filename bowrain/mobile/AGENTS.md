# Bowrain mobile

The Bowrain app for iOS and Android, built with Expo (React Native). Review is
its first feature: one card per block, swiped or tapped to decide. The design
is `docs/internals/bowrain-mobile-review.md`, including the server API it
reads. Read that note before changing a screen.

## Rules

- **Development builds, never Expo Go.** The app uses native modules Expo Go
  does not carry. Build once with `vpr ios` or `vpr android` (`expo run:*`),
  then `vpr start` serves JavaScript to that build. In the cloud the build is
  `eas build --profile development`.
- **Never edit `ios/` or `android/`.** They are generated by `expo prebuild`
  (Continuous Native Generation) and gitignored. A native setting goes in
  `app.config.ts` or in a config plugin.
- **Rebuild after a native dependency changes.** Add packages with
  `npx expo install <pkg>`, which picks the version the SDK supports, then run
  `vp install` at the repo root and build again. A JavaScript reload does not
  pick up native code, and a stale binary looks like a bug in your change.
- **Reanimated 4's Babel plugin is `react-native-worklets/plugin`.**
  `babel-preset-expo` adds it, so there is no `babel.config.js`. Blog posts
  about `react-native-reanimated/plugin` describe Reanimated 3.
- **The app holds no product rules.** Which cards make the deck and in what
  order, which group a card is in, which fixes apply, who may approve, what a
  decision does: the server computes all of it, so Bowrain web and the app
  answer the same way. The app shows what the server says and sends change
  sets. A rule the server does not have yet is added on the server first.
- **Render runs through a `RunSpec`**, never a loop over `run.text`
  (`packages/kapi-format/src/run-projection.ts`). Placeholders and inline codes
  are chips and stay locked in the editor.
- **Licence.** This directory is Apache-2.0 under its own `LICENSE`, although
  it sits inside the AGPL `bowrain/` tree, because an App Store app cannot be
  GPL-family. It imports nothing from `bowrain/` outside itself: no
  `@neokapi/ui`, no `@neokapi/bowrain-app`. The API client is
  `@neokapi/bowrain-client` (`packages/bowrain-client`), and the content
  model is `@neokapi/kapi-format`. `scripts/check-ts-license-boundary.sh`
  fails on any crossing.
- **Expo changes every SDK.** Check the `expo` version in `package.json` and
  read the matching docs (`https://docs.expo.dev/versions/v58.0.0/`,
  `https://docs.expo.dev/llms.txt`) rather than recalling an API. The Expo
  plugin for Claude Code (`.claude/settings.json`) brings Expo's skills and MCP
  server.

## Layout

- `src/app/`: expo-router screens. Sign-in, workspaces, projects, languages,
  and the deck (`[ws]/[project]/[locale].tsx`).
- `src/components/`: the card, the swipe gesture, the action bar, the fix
  sheet, the run renderer and the run editor.
- `src/lib/`: the session (`auth.tsx`, `callback.ts`), the query client and
  its on-device persistence, and the offline decision queue (`decisions.ts`).
- `i18n/en.json`: the English UI catalog. The dogfood recipe's
  `bowrain-mobile` collection writes the other languages beside it. Never
  write a target catalog by hand.
- `e2e/`: Maestro flows, run against a development build and the local stack.

## Commands

From this directory (`vpr <script>` runs a package script):

```bash
vpr test          # jest-expo unit and component tests
vpr typecheck     # tsc --noEmit
vpr export        # iOS and Android bundles, the check that Metro resolves the workspace
vpr ios           # prebuild and run a development build on the iOS simulator
vpr start         # Metro for an installed development build
```

From the repo root: `vp install`, `vp check`, and
`scripts/check-ts-license-boundary.sh`.

Sign-in against the local stack (`make -C bowrain stack-up`) uses
`EXPO_PUBLIC_BOWRAIN_SERVER_URL`, default `http://localhost:8080`. On the
Android emulator the host machine is `http://10.0.2.2:8080`.
