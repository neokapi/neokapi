# kapi 1.3.0

_Changes since [`v1.2.0`](https://github.com/neokapi/neokapi/releases/tag/v1.2.0)._

kapi 1.3.0 keeps a project's writing consistent across people, AI agents and languages. kapi reads the project's files, keeps the rules they are written by in a context graph beside them, and checks every edit against it. The same rules reach you in Kapi Desktop, on the command line and in your assistant's session, and a project needs only one language to use them. Languages are added when you need them.

A recipe written for 1.2.0 that uses a retired shape is refused when it loads, and the message names the replacement. There is no migration: the context store, the redaction vault and the project state are rebuilt by the current kapi.

## See what applies, decide, and check every edit

- `kapi look` shows the project at a glance: its files and blocks, the rules in force, the findings, and the suggestions waiting for a person. With a file, it shows that file with its rules in the margin and its findings under the block they are about.
- The first look at a project with no rules files what kapi sees in the files as suggestions, such as one word written two ways. `kapi context suggest` does the same on demand, and a deeper look with AI files what term extraction and voice inference notice.
- `kapi rules` is where you decide: keep a suggestion as a rule, drop it, or leave it for later, one question per suggestion with the consequence stated. It also lists, narrows and drops the rules a project keeps.
- `kapi check` fails on a failing finding, not on a severity threshold. A word rule fails unless it is marked advisory; a tone rule of a voice profile reports until a person marks it `fails: true`; a suggestion nobody has decided reports and never fails. Each finding in the report says whether it fails. The checks kapi runs are listed in the reference.
- `kapi fix` applies the fixes kapi can make on its own, such as a term with a named replacement.
- Word rules are terms. The voice profile keeps tone, style measures, pattern rules and guidance; the terms store holds every word rule, including the ones a starter pack brings. A term rule never matches inside a bare domain name.
- A project's context lives in a workspace store outside the checkout, and `.kapi/` is a cache. Every change to the context is a recorded operation: `kapi context log` lists them and `kapi context reset` sets them aside. `kapi store` maintains the store, and `kapi context search` answers what the project says about a word.
- `kapi context atlas` and `kapi context places` show the context on its axes, over time, and on a map of the places a project names.
- `kapi trust` lists, allows and revokes which projects may run the commands their recipes name.

## Kapi Desktop

- Open any folder. A project opens on its Map: the counts, the rules in force, what an assistant noticed, and one row per file. Decide asks one question per suggestion. The Reader shows a file with its rules in the margin and its findings in place, and Fix applies a fix there.
- Assistants: connect an assistant once, then watch its sessions, with what each session's check caught and the runs behind the counts.
- Share shows how far the project's context reaches, as a ladder with the current rung marked, and Preview shows the project the way a Bowrain project page would, from this Mac or from the server once the project is connected.
- Languages appears as a plus until the project has a target language. Bring up to date opens on a project that has one.
- The app opens on your context: the workspace's terms, the history, and the content memory, each as a list with a detail pane. A project can choose a format engine where more than one reads its files.
- The desktop opens only http, https and mailto links.

## Assistants and agents

- `kapi connect` puts an assistant on the project. kapi writes the project's rules into a section of `AGENTS.md` and `CLAUDE.md`, rewrites it when the rules change, and runs `kapi check` on every edit through the assistant's hooks. `kapi hook post-edit` is the per-edit gate, and the Stop hook records what each run caught.
- The MCP server serves its tools by set, answers the context as the task needs it, and reports a session's summary with what the hook caught. kapi records which agent drove a context command. Codex is wired for MCP beside Claude.
- Agents may record what they notice, and a person decides what becomes a rule. An agent's write to a voice profile is refused before it reaches the store.
- `kapi share --via git`, `--via folder` and `--via s3` share a project's context with every checkout, and `kapi context sync` reads what the team decided and sends what this machine recorded. `kapi open` opens the folder in Kapi Desktop.

## Languages when you need them

- Add a target language to the recipe. `kapi up` translates what changed, reuses what was approved before, and holds back what needs a person. A language held back says it is waiting for review, in every output and on every screen.
- `defaults.translate_after` names the source state a translation starts from; it replaces `defaults.source_gate`, and a value outside the ladder is refused when the recipe loads.
- A translation whose source stamp disagrees with its block is stale, and `kapi status` columns name what they show. An approved translation shows as approved.
- `kapi exec qa` and `kapi exec review` take `--target` and never write the source over a translation. `kapi exec term-check` takes `--term-rules`, and the consistency checks key on code-aware text.
- A redaction policy covers everything that leaves the project: a provider request, a tool with no known contract (refused), an external command, and a `.kpz` written under the policy, which carries placeholders while the vault keeps every file's originals outside the package. A program that alters a placeholder fails the run. A vault written by another kapi version is refused.

## The engine

- The Markdown writer checks its output against the parser before writing, and keeps inline HTML, strikethrough, definitions, nested emphasis, code spans, hard breaks, admonition headers and link destinations as the parser read them. JSON and HTML edits are byte-faithful outside the edited block.
- Documents are decoded and re-encoded by their declared encoding. A native format is preferred over a plugin format for the same file, through one detection resolver; `kapi formats explain` says which engine reads a file.
- Editing surfaces read block content as runs, so placeholders, paired codes and plurals survive every projection.
- Every serialization format shares one schema-version refusal. The Okapi parity suite now lives in okapi-bridge.
- Building kapi needs Go 1.27.1 or later.

## Installation

**Homebrew (kapi CLI, with the PDF plugin):**
```
brew install neokapi/tap/kapi-cli
```

**Homebrew (Kapi Desktop, macOS):**
```
brew install --cask neokapi/tap/kapi
```

The bowrain plugin and Bowrain Desktop are released separately, under the tag `bowrain-v1.3.0`:
```
brew install neokapi/tap/bowrain-cli      # kapi and the bowrain plugin
brew install --cask neokapi/tap/bowrain   # Bowrain Desktop
```

To follow the beta channel, install `neokapi/tap/kapi-cli-beta` or the `neokapi/tap/kapi@beta` cask instead.

CLI archives for macOS and Linux, `.deb` and `.rpm` packages for Linux, and Kapi Desktop for macOS and Linux are attached below. Verify a download against `checksums.txt`; each CLI archive also has a signature bundle (`.sigstore.json`). Signed Windows builds of the CLI and Kapi Desktop are added to this release after it is published.
