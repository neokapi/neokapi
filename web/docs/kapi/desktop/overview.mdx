# Kapi Desktop

Kapi Desktop shows your projects' writing rules: terms, voice, and the
decisions people made. While your assistants work, they suggest new rules. In
the app you keep each one, change it, or drop it. A rule you keep applies to
every file and every assistant.

The app, the [kapi CLI](/kapi/cli) and the [MCP server](/reference/mcp) use
the same project data, so you get the same answer from each.

This page shows where to find each part of the app. [Your first
project](/kapi/get-started/first-project) walks through one project step by
step, and [the tour](/kapi/desktop/tour) shows each part in a video.

## Install

On macOS, the cask installs the app and bundles the `kapi` CLI:

```bash
brew install --cask neokapi/tap/kapi
```

[Installation](/kapi/get-started/installation#install-kapi-desktop) covers the
Windows installer, the macOS DMG, the Linux tarball and the release channels.

## Your context {#your-context}

The home lists every project in the workspace and what is new in each.

    dark: "/img/desktop/dark/context-home.png",
  }}
/>

- **Counts** for the workspace: projects, rules in use, terms, open
  suggestions, and items that need you. The last count is highlighted when two
  suggestions disagree.
- **What's new** has a row for each project with something new, newest first.
  Each row shows the assistant, what it suggested, and **Review** or
  **Decide**. A live dot means an assistant is working in that project. Press
  `j` and `k` to move between rows and Enter to open one.
- **Projects** lists every project you opened in the CLI or the app, or that
  an assistant set up. Each row shows the project's voice profile, its rules,
  and who the rules are shared with. Clones and worktrees of one project share
  a row and one set of rules, and the row's `⋯` menu lists each copy. If a
  project has no copy on this machine, it opens without the actions that need
  files.
- **Holds in every project** lists the rules that apply to all your projects.
- **Get started** has three guided tours for your first visit: try the sample
  and find your way around it, decide what becomes a rule, and connect an
  assistant. Each tour you finish gets a check. **Hide** removes the card, and
  **Show it again** in **App Settings** brings it back.
- **History**, next to the title, opens the sessions of every project.

Each project opens in a tab, and the app reopens your tabs from last time. The
sidebar has one entry per page: **Overview**, **Context**, **Review** and
**Project Settings**, with **Help** and **App Settings** at the bottom.

## Overview {#overview}

A project opens on its **Overview**, the desktop form of `kapi look`.

<ThemedImage
  alt="A project's Overview: the files, blocks, rules and findings counts, the Suggestions list, and the Files list"
  sources={{
    light: "/img/desktop/light/overview.png",
    dark: "/img/desktop/dark/overview.png",
  }}
/>

- **Counts** of files, blocks, rules and findings. Click a count to see what
  it counts. The findings count is highlighted when there are any.
- **First steps**, on a new project: decide what becomes a rule, check the
  files, fix what fails, connect an assistant, and share the rules. Click a row
  to go to that step, or **Guide** to take the tour of the project. The list goes away when you have
  decided the rules, connected an assistant and shared the rules, or when you
  click **Dismiss**. The last line of `kapi look` shows the same next step.
- **Suggestions** lists the ones you haven't decided yet, each
  with a sentence where it was seen. **Decide** opens it in
  [Decide](#decide).
- **Deeper look with AI** uses your AI model to read the files and suggest
  more rules, like
  [`kapi context suggest --ai`](/kapi/context-decisions#what-kapi-sees-in-the-files).
- **Files** lists each content file with its blocks and findings, most
  findings first. **Open** shows it in the [Reader](#reader).
- **Run on everything** runs the [checks](#checks) on every file.

## Checks and findings {#checks}

A check reads every block of every file and compares it with the project's
rules: its terms, its voice profile and the rules you kept in Decide. Each
place where a block breaks a rule is a finding.

- **Run on everything** on the Overview checks the whole project. The first
  time you open a project in a session, the Overview also runs the checks
  once.
- Each file on the Overview shows its own findings. Open it to see them in
  place.

A word rule fails the check unless it is marked advisory. A tone rule only
reports until someone marks it to fail. A suggestion nobody has decided
reports and never fails. `kapi check` runs the same checks on the command
line; [Verify content](/kapi/recipes/verify-content) covers it.

## The Reader {#reader}

The **Reader** shows one file's blocks in file order and marks each finding on
its words, with a row under the block.

- **Fix** beside a finding replaces the words with the rule's wording.
- **Fix _n_ in this file** fixes every finding in the file at once.
- **Rules here** shows the same rules as `kapi context <path>`.

A fix keeps the rest of the file and its formatting as they were. Findings
about tone or style, and findings on words that hold a link or other
formatting, have no **Fix**. Edit those words yourself.

## Decide {#decide}

**Decide** asks you about each suggestion an assistant recorded: a name
spelled two ways, a word to avoid, a note about tone. Each one stays a
suggestion until you answer it.

**Decide** is at the top of the **Context** page, and **Decide** on a
suggestion on the Overview opens it there. Like `kapi rules`, it asks one
question per suggestion, and you pick one of three answers:

| Answer | Key | What it does |
| --- | --- | --- |
| **Keep** | `k` | Makes it a rule in the terms, the voice profile or the content memory. If two suggestions disagree, keeps the one you picked. |
| **Not a rule** | `n` | Removes it. Checks stop reporting it. |
| **Later** | `l` | Saves nothing. Checks keep reporting it, and Decide asks again next time. |

Until you decide, checks report a suggestion but never fail on it. Above the
answers you see what keeping it does, and **Seen in** shows the sentence and
file it came from. A rule you keep applies to the next check and to every
assistant that reads the project. To decide, you need a copy of the project on
this machine. [Review your assistant's
suggestions](/kapi/desktop/recipes/review-your-assistants-suggestions) walks
through it on the sample.

## Search and Explore {#search-and-explore}

**Search** finds rules by word or by file. Search for a word to see the terms
that cover it and approved text that uses it. Search for a file to see the
rules for that file.

**Explore** shows your rules by product, market and other dimensions, and over
time: a timeline, flows, a matrix, a map of markets, and a list of records.
One search filters every view. [Explore your
context](/kapi/desktop/recipes/explore-your-context) goes through each view,
and `kapi context atlas --json` prints the same data.

## Voice, terms and content memory {#voice-and-terms}

**Voice**, **Terms** and **Content Memory**, on the **Context** page, let you
read and edit those stores directly.

- **Voice** shows the voice profile that applies: tone, style rules, pattern
  rules, examples, and the adjustments for a language, channel or persona.
  Editing it writes the YAML file in your project, the same file a reviewer
  reads in a pull request.
- **Terms** lists the words decided for the project, one concept per row.
  Select a concept to see its definition, the forms to avoid with what to
  write instead, and its terms in each language. **Relate** links it to
  another concept.
- **Content Memory**, in a project with target languages, holds approved
  wording one pair per row: a source sentence and its translation.

[Keep source on brand](/kapi/recipes/keep-source-on-brand) shows the voice
profile and terms at work in a check.

## Project Settings {#project-settings}

**Project Settings** holds the project's languages, its content and flows,
the assistants connected to it, and who its rules are shared with.

- **Content** shows the collections, the files in each, and each file's
  format. Open a file to preview the text kapi reads from it.
- **Flows** holds the project's flows. You can edit them and run them, with
  progress for each file. See [Build a flow
  visually](/kapi/desktop/recipes/build-a-flow-visually).
- **Assistants** and **Share** have sections of their own:
  [Assistants](#assistants) and [Share](#share).

**App Settings**, at the bottom of the sidebar, holds the app's appearance and
language, your AI models, plugins, the formats kapi reads with your saved
settings for each, and the list of languages you pick from, where you can
hide one or add your own.

## Assistants {#assistants}

**Assistants**, a tab of **Project Settings**, connects Claude Code, Cursor,
VS Code, Codex, Agent skills or Claude Desktop to the project.

- **Connect** writes the files that assistant reads, the same files
  `kapi connect` writes.
- **Show what it reads** shows the section kapi writes into `AGENTS.md` and
  `CLAUDE.md`, and the rules for any one file.
- **Sessions** lists what you and the assistants recorded, one session per
  row, and, if the check on every edit is on, what it found. Select a session
  to see what it changed and the checks it ran.
- **Reset to before this session** undoes the session's changes to your
  rules, and **Take this reset back** undoes the reset. It's the same as
  `kapi context reset --before <session>`.

What a connected assistant suggests appears on the Overview under
**Suggestions** and on the home under **What's new**. You answer it in
[Decide](#decide). See [Connect an
assistant](/kapi/desktop/recipes/connect-an-assistant).

## Share {#share}

**Share**, a tab of **Project Settings**, shows who can read the project's
rules, at one of three levels:

- **On this Mac**: every clone and worktree on this machine reads them.
- **With your team**: git, a shared folder or S3 carries them to every machine
  that syncs the project. **Sync now** runs `kapi context sync`.
- **In a managed workspace**: a server that holds the rules for the team,
  with a queue for the decisions and a record of who kept what.

Everything else stays on your machine, in your project and your workspace.
See [Share context with your
team](/kapi/desktop/recipes/share-context-with-your-team).

## In every language {#languages}

To translate a project, open **Project Settings**, add the language under
**Translate into**, and click **Save Changes**.

The Overview then shows **Bring up to date**, the desktop form of `kapi up`.
It reuses earlier translations from the content memory, translates the rest,
and holds back for **Review** what needs a person. **Plan…** shows the work
to do and estimates the tokens it uses before anything runs. Next to it,
three counts show the work: blocks to translate, blocks waiting for a person
to review, and languages held back. **Review** shows the text that isn't
ready to ship yet.

A project without target languages works as it is. **Review** lets you pick
languages to translate into, and **Bring up to date** with its counts appears
when you add the first one. A language that is behind is pending work, and it never breaks a
build. [Add languages](/kapi/get-started/add-languages) covers the same steps
on the command line.

## Help and guided tours {#help}

**Help**, at the foot of the sidebar, opens the Help panel. The info button
beside a page's title opens it on the topic for that page. The panel holds two
lists:

- **Guides**: tours of common tasks, such as finding your way around a
  project, deciding what becomes a rule, checking the files and fixing a
  finding, translating into another language, and connecting an assistant.
  **Start** opens the page the tour is about and lights each control in turn,
  with a short note beside it. **Next** and **Back** move through the steps,
  and the × on the note or Esc ends the tour. A finished tour gets a check.
- **Topics**: the sections of the [Kapi Desktop
  overview](/kapi/desktop/overview) in these docs, read in the app. Each ends
  with a link to the same section on the website.

A tour starts only when you click one. The **Guide** action on a project's
first steps and the tours under **Get started** on the home start the same
tours.

## The command line {#command-line}

Kapi Desktop and the `kapi` command work on the same project files, so you
can switch between them.

| In the app | On the command line |
| --- | --- |
| **Run on everything** | `kapi check` |
| **Fix** | `kapi fix` |
| **Decide** | `kapi rules` |
| **Rules here** | `kapi context <path>` |
| **Connect** an assistant | `kapi connect` |
| **Bring up to date** | `kapi up` |
| **Share** | `kapi share` |

Run `kapi --help` in a project for the full list, or see [CLI or
desktop](/kapi/get-started/cli-vs-desktop).

## The sample {#sample}

**Try the sample** opens KapiMart, a sample store with a voice profile, terms,
a content memory and five target languages. It comes with two recorded
assistant sessions, and one disagrees with the other, so Decide has a question
for you right away. The sample doesn't call an AI model.

## The project file

Everything you set up is saved in the project's `kapi.yaml` file. Commit it to
share it with your team, open it again in Kapi Desktop, or run it from the
command line with `kapi up -p kapi.yaml`. [Kapi Project
Files](/reference/project-file) is the full reference.
