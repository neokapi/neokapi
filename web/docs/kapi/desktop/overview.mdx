# Kapi Desktop

Kapi Desktop shows the rules your projects keep: their terms, their voice and
the decisions people made about them. Your assistants record what they notice
while they work, and in the app you decide about it: keep what is right,
change it, or drop it. A rule you keep holds in every file, for every
assistant.

The app, the [kapi CLI](/kapi/cli) and the [MCP server](/reference/mcp) read
and write the same project data, so a panel, a command and an MCP tool give the
same answer to the same question.

This page says where each part of the app is. [Your first
project](/kapi/get-started/first-project) takes one project through it step by
step, and [the tour](/kapi/desktop/tour) shows each part in motion.

## Install

On macOS, the cask installs the app and bundles the `kapi` CLI:

```bash
brew install --cask neokapi/tap/kapi
```

[Installation](/kapi/get-started/installation#install-kapi-desktop) covers the
Windows installer, the macOS DMG, the Linux tarball and the release channels.

## Your context

The app opens on **Your context**, which covers every project in the
workspace.

<ThemedImage
  alt="Your context: counts across the workspace, What's new with a row per project, and the Projects list"
  sources={{
    light: "/img/desktop/light/context-home.png",
    dark: "/img/desktop/dark/context-home.png",
  }}
/>

- **Counts** across the workspace: projects, rules in force, terms,
  suggestions advising, and what needs you. The last one is highlighted while a
  disagreement waits.
- **What's new** has a row for each project with something you have not seen
  or decided, newest first: the assistant that noticed it, what it noticed,
  and **Review** or **Decide**. A row with a live dot means an assistant is
  working there. `j` and `k` move between rows, and Enter opens one.
- **Projects** lists every project the CLI, the app or an assistant has
  registered, with its voice profile, its rules and where its context is
  shared. Clones and worktrees of one project share a row and one context, and
  the row's `⋯` menu lists each checkout. A project with no checkout on this
  machine opens as a context-only tab, without the actions that need files.
- **Holds in every project** lists the rules applied to the whole workspace.
- **Start here** is three steps for a first visit: try the sample, connect an
  assistant, and come back to what it noticed. Dismiss it when you are done;
  Settings brings it back.
- **History**, beside the title, opens the sessions of every project.

A project opens as a tab, and the tabs you had last time come back. The
sidebar has one entry per page: **Overview**, **Context**, **Review** and
**Project Settings**, with **App Settings** at the bottom.

## Overview

A project opens on its **Overview**, the desktop form of `kapi look`.

<ThemedImage
  alt="A project's Overview: the files, blocks, rules and findings counts, What your files do with the suggestions, and the Files list"
  sources={{
    light: "/img/desktop/light/map.png",
    dark: "/img/desktop/dark/map.png",
  }}
/>

- **Counts** of files, blocks, rules and findings, each a link to what it
  counts. Findings is highlighted while it is above zero.
- **First steps**, on a new project: decide what becomes a rule, check the
  files, fix what fails, connect an assistant, and share the rules. Each row
  opens its step, and **Guide** opens [Your first
  project](/kapi/get-started/first-project). The list ends once the rules are
  decided, an assistant is connected and the rules are shared, and **Dismiss**
  hides it sooner. `kapi look` ends with the first step left.
- **What your files do** lists the suggestions nobody has decided yet, each
  with the sentence it was seen in. **Decide** opens Decide on it.
- **Deeper look with AI** reads the files with the connected AI model and
  records what it proposes as suggestions, the same as
  [`kapi context suggest --ai`](/kapi/context-decisions#what-kapi-sees-in-the-files).
- **Files** lists each content file with its blocks and findings, most
  findings first. **Open** shows it in the Reader.
- **Run on everything** runs the checks over every file. The Overview runs
  them once on its own the first time a project opens in a session.

The **Reader** draws a file's blocks in order, with each finding marked on the
words it is about. **Fix** applies a rule's replacement, and **Fix _n_ in this
file** applies every one at once, through the file's format. **Rules here**
lists what `kapi context <path>` prints for the file.

## Decide

**Decide** is the first section of the **Context** page. It asks one question
per suggestion, as `kapi rules` does, and takes one of three answers:

| Answer | Key | What it does |
| --- | --- | --- |
| **Keep** | `k` | Makes it a rule in the terms, voice profile or content memory. On a disagreement, keeps the side you picked. |
| **Not a rule** | `n` | Sets it aside. It stops advising at once. |
| **Later** | `l` | Records nothing. It keeps advising, and Decide asks again next time. |

A suggestion advises from the moment it is recorded: a check reports it and
fails nothing. Before you answer, a line says what keeping it does, and **Seen
in** names the sentence and file it came from. Deciding needs a checkout of
the project on this machine. [Review what your assistant
noticed](/kapi/desktop/recipes/review-what-your-assistant-noticed) walks
through it on the sample.

## The rest of the Context page

**Search** answers by word and by file. A word returns the terms that cover it
and the approved wording that uses it. A file returns what applies there.

**Explore** shows the context on the project's axes and over time: a timeline,
flows between axes, a matrix, a map of markets, and the records in scope. One
query drives every view. [Explore your
context](/kapi/desktop/recipes/explore-your-context) goes through each view,
and `kapi context atlas --json` prints the same data.

**Voice**, **Terms** and, in a project with target languages, **Content
Memory** show the project's stores, where you read and edit them directly.

## Project Settings

- **Assistants** connects Claude Code, Cursor, VS Code, Codex, Agent skills or
  Claude Desktop, writing the same files `kapi connect` writes. **Sessions**
  lists what each session recorded and, where the check on every edit ran, what
  it caught. **Show what it reads** shows the rules files and the brief for one
  file. See [Connect an assistant](/kapi/desktop/recipes/connect-an-assistant).
- **Sessions** shows one session's operations and check runs. **Reset to
  before this session** puts the context back as it stood before an
  assistant's session, and **Take this reset back** undoes the reset. It is the
  same as `kapi context reset --before <session>`.
- **Share** shows how far the context reaches: on this Mac, shared with your
  team through git, a folder or S3, or a managed workspace. **Sync now** runs
  `kapi context sync`. See [Share context with your
  team](/kapi/desktop/recipes/share-context-with-your-team).
- **Content** shows the collections, the files they match and the format kapi
  detected for each. Opening a file previews it as the engine reads it.
- **Flows** holds the flows the project runs, to edit and run with progress
  for each file. See [Build a flow
  visually](/kapi/desktop/recipes/build-a-flow-visually).

**App Settings**, at the bottom of the sidebar, holds the app's appearance and
language, your AI models, plugins, the formats kapi reads with your saved
settings for each, and the list of languages you pick from, where you hide
one or add your own.

## In every language

A project that declares target languages gets the multilingual half. The
Overview shows **Bring up to date**, the desktop form of `kapi up`, with
**Plan…** for the pending work and a token estimate before anything runs.
Beside it, three counts separate the run's work from a person's: blocks to
translate, blocks waiting for review, and languages held back. **Review**
takes what the run could not carry to the ship gate.

A project that declares none is complete as it is. **Review** offers the
languages to translate into, and adding the first one brings the rest.

## The sample

**Try the sample** opens KapiMart, a sample store with a voice profile, terms,
a content memory and five target languages. It arrives with two assistant
sessions recorded against its files, one of them disagreeing with the other,
so Decide has something to ask on first open. Nothing calls a model.

## The project file

Everything you configure is written to a portable `kapi.yaml` recipe. Commit
it to share it with your team, reopen it in Kapi Desktop, or run it from the
command line with `kapi up -p kapi.yaml`. [Kapi Project
Files](/reference/project-file) is the full reference.
