# Store AI credentials

**Goal:** save a provider's API key once, in the OS keychain. Every `translate`,
`qa` or `rewrite` step that needs the key finds it there, and the committed
recipe never holds it. You can add the key in Kapi Desktop's **AI Models**
settings or with `kapi credentials` on the command line; both write to the same
store.

For how providers work and how kapi resolves a key, see
[Choose a translation provider](/kapi/recipes/choose-a-translation-provider).

## Steps

0. **Check whether you need a key.** On first open, the **Connect your AI** card
   offers what it detects: a Claude Code sign-in ([uses your Claude
   subscription](/kapi/get-started/use-with-claude#let-kapi-run-claude)) or a local
   Ollama model. Either takes one click and stores nothing. The steps below are
   for API keys.
1. **Add the credential.** From **Settings → AI Models**, add a credential: pick
   the provider (Anthropic, OpenAI, Gemini, …) and paste its key.
2. **Stored in the keychain.** The key is saved to the OS keychain and never
   written to the `kapi.yaml` recipe, so the recipe stays safe to commit and
   share.
3. **Use it.** A `translate` step (in the [flow editor](/kapi/desktop/recipes/build-a-flow-visually))
   or any AI-backed tool finds the credential itself, so you never type a key on
   a command line.

## Where the key lives

Keys live in the OS keychain, and the recipe carries only the provider name. The
app shows which providers are configured. The CLI's `kapi credentials` uses the
same keychain store, so a key you add here is available to command-line runs
too.
