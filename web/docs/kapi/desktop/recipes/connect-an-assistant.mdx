# Connect an assistant

**Goal:** put the assistant you write with on a project, so it follows the
project's rules and leaves what it notices for you to review. You do this once
per project and assistant, from the project's **Assistant** section, with no
terminal.

## What connecting writes

Connecting gives the assistant a way to reach kapi: an MCP entry that starts
kapi's server for this project. Each assistant reads it from its own file:

| Assistant | What Connect writes |
| --- | --- |
| **Claude Code** | `.mcp.json` with the `kapi` server, and the kapi skill in `.claude/skills/kapi/` |
| **Cursor** | `.cursor/mcp.json` with the `kapi` server |
| **VS Code** | `.vscode/mcp.json` with the `kapi` server |
| **Codex** | `.codex/config.toml` with the `kapi` server, read once you trust the repository |
| **Claude Desktop** | a `kapi` entry in your own `claude_desktop_config.json`, after you confirm |

The first four files sit in the project, and you commit them like any other
file, so a teammate who opens the project gets the same entry. Each holds a
command and nothing else: no shell, no environment, no credential. An entry
called `kapi` that you wrote or changed yourself is left as it is.

Claude Desktop reads one file for every project, outside them all:
`~/Library/Application Support/Claude/claude_desktop_config.json` on macOS and
`%APPDATA%\Claude\claude_desktop_config.json` on Windows. Kapi Desktop names
that file and asks before it changes it. The entry names the `kapi` binary by
its full path, since an app started from the Dock or the Start menu does not
read your shell's `PATH`.

Every assistant also reads the project's **rules files**. kapi writes the
project's rules into `AGENTS.md` and `CLAUDE.md`, at the root and in each
folder whose rules differ, where an assistant loads them as it starts, with no
tool call.

## Steps

1. **Open the project.** Connecting writes files into the project, so it needs
   a checkout on this machine. A context-only tab says so in place of the
   rows.
2. **Open Assistant.** In the project's **Context** hub, open **Assistant**.
   **Connected assistants** has a row for each assistant. The dot before a
   name is filled when that assistant is connected and an outline when it is
   not.
3. **Click Connect** on the row for yours. The dot fills, **Connected**
   follows the name, and the row lists the files it wrote. Hover over
   **Connected** to see the files that carry the connection. For Claude
   Desktop, confirm the file it names first.
4. **Check the rules files.** On the **Rules files** tab, expand a row to read
   the section kapi wrote. When a file is not written yet, click **Write them
   now**.
5. **Open your assistant in the project folder.** Claude Code asks you to
   approve the project's MCP server the first time. Review `.mcp.json` before
   you say yes, the way you would any file a repository ships. Claude Desktop
   reads its file when it starts, so restart it.

## What the assistant then does

The kapi skill asks an assistant for four habits:

1. **Follow the rules files.** It writes by the rules in `AGENTS.md` and
   `CLAUDE.md` without asking first, and asks kapi only about a file no
   section covers.
2. **Record what the files do every time.** A name, a spelling, a word the
   files use where writers often use another: what the files keep to and the
   rules do not list yet.
3. **Record your corrections.** When you change a wording in its draft, it
   records the change as a suggestion.
4. **Check what it changed.** It runs `kapi check` on each file it changed and
   fixes what the check reports.

An assistant without the skill reads the rules files, which end by asking it
to check what it changed and to record what it notices.

What the assistant records appears in Kapi Desktop within a second or two:
under **What's new** on the home, and in the project's own What's new, as a
suggestion with the file and sentence it was seen in and "noticed by" the
assistant's name. A suggestion advises at once and fails no check. It becomes a
rule when you keep it. [Review what your assistant
noticed](/kapi/desktop/recipes/review-what-your-assistant-noticed) walks
through deciding.

## The same on the command line

`kapi init` writes the same wiring for the assistants it detects, and
`--agents` names them yourself:

```bash
kapi init                                # Claude Code, plus the assistants whose folders the project keeps
kapi init --agents claude-code,cursor    # exactly these
kapi init --agents none                  # no assistant configuration
```

`kapi init --no-rules-files` leaves out the rules files. See [what `kapi
init` wires up](/kapi/get-started/use-with-claude#what-kapi-init-wires-up)
and [rules files for agents](/kapi/context#rules-files).
