# Guides

Each guide takes a single task (check content, translate it, review what a
machine couldn't decide) and shows the same job through three doors, in order:
**Kapi Desktop**, **your AI agent**, and the **CLI**. The interactive embeds run
the real `kapi` binary in your browser: no install, no server, no API key.

For what kapi is and how the surfaces relate, see the
[Kapi overview](/kapi/overview). For every command and flag, see the
[command reference](/commands).

## Get oriented

Inside a project, `kapi look`, or `kapi` on its own, prints the project: its
files, the blocks in them, the rules in force, the findings a check reports
and the suggestions waiting for you. `kapi look <path>` prints one file with
its findings and rules in place.

In the installed kapi, `kapi --help` shows the writing commands, adds the
language commands when the recipe declares a target language, and
`kapi help --all` lists every command, including the engine's. The tour below
runs a copy of `kapi` in your browser, with no install and no server. That copy
prints the full list from `kapi --help`. Then `kapi formats` and `kapi tools`,
two engine commands, list the format readers and the processing tools you can
run on extracted content. Step through the tour from the rail, or press
**Run all**.

## Ad-hoc or project?

A **kapi project is the recommended working model** for any repository or
content set you work on repeatedly: the content patterns, the voice, terms and
coordinates that govern them, your flows and, if you translate, your languages
in a committed recipe; git-style discovery from any subdirectory; and a store
that accumulates content memory, terminology, and approvals across runs.
[Create your first project](/kapi/get-started/first-project) walks the setup;
[Projects](/kapi/projects) is the concept. kapi also runs **ad-hoc** (a command
on the files you name, nothing saved), the quick path for one-offs, scripting,
and a fine on-ramp. Guides note the project form where it differs.
