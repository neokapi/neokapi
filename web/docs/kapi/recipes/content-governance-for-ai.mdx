# Content governance for AI

**Goal:** configure writing rules and automated checks for AI-assisted content. Checks identify violations of supported rules; people review meaning and guidance that cannot be checked automatically. This recipe covers voice profiles, terms and checksets:

| Artifact | Encodes | Lives in | Enforced by |
|---|---|---|---|
| **Voice profile** | tone, style measures, pattern rules | the project's voice store | the `voice.rules` analyzer in every check |
| **Terms store** | approved terms per language, and every word to avoid (forbidden, competitor, retired) | the project's terms store | the `terms` analyzer in every check, `term-check` and the terminology gate |
| **Checkset** | length budgets, required/forbidden patterns, hygiene | the recipe, in git | `kapi check`, in the loop and in CI |

The first two live in your [workspace](/kapi/project-store), one set per project, shared by every checkout. `kapi context export` backs them up and [`kapi context snapshot`](/kapi/context-portability#writing-context-out) writes them out as files for a team that wants them in git.

The rules run in **two directions** around the agent: injected *before* it writes (the voice guide and approved terms go into its context, so drafts start compliant) and gated *after* (`kapi check` scores the result, block by block, exit code and all). Style linters for prose stop at regex over plain text; kapi's checks are format-aware and block-anchored: they read the content inside `.docx`, JSON catalogs, and HTML, locate each finding to an addressable block an agent can fix, and extend across every target language.

<Tabs groupId="surface" queryString>
<TabItem value="desktop" label="Desktop" default>

1. **Bind the artifacts.** In **Project Settings**, bind the voice profile; the approved terms the recipe binds show under **Context → Terms**. From then on the project enforces both everywhere.
2. **Watch the gates.** The **Checks** view shows standing against the rules continuously; the ship-gate cells fold the voice and terminology gates into each locale's release bar.
3. **Review the exceptions.** Units that fail a rule surface findings-first in the [Review queue](/kapi/recipes/review-and-approve); the human reads what the rules flagged rather than the bulk.

</TabItem>
<TabItem value="agent" label="Agent (Claude)">

With the rules bound in the project, governance is automatic: the [skill](/kapi/get-started/use-with-claude) pulls the guide and terms into context before writing and runs the gate after. Two prompts to bootstrap the artifacts themselves:

> Draft a voice profile from our README and landing copy, and bind it in the recipe.

> Extract candidate terms from `docs/` and add the ones I approve to our terms store.

The Claude Code plugin's Stop hook checks the ship gate before task completion. Agents record proposed rules with `context_observe` or `context_correct`; a person reviews them with `kapi context log` and establishes them with `kapi context keep`. See [Growing context](/kapi/context-decisions) for review and undo operations.

</TabItem>
<TabItem value="cli" label="CLI">

Author the artifacts, bind them once, and gate on them everywhere:

```bash
kapi voice new --pack technical-docs -o brand/voice.yaml   # scaffold, then edit
kapi voice import brand/voice.yaml                         # into the project's voice store
kapi terms import terms.csv -s en --monolingual --header   # into the project's terms
kapi check docs/*.md                                       # the loop's gate
kapi check --ship                                          # the release bar, in CI
```

Bind in the recipe so no invocation needs flags. The import prints the id it
filed the profile under, and `defaults.voice.profile` names that id:

```yaml title="kapi.yaml"
defaults:
  voice:
    profile: acme-docs
```

From then on `kapi voice edit` opens the stored profile in your editor and reads
your changes back as one recorded change, so the profile is authored in one
place and every check reads it from there.

`kapi check` exits non-zero on a gate failure, so the same rules hold in CI with no assistant in the loop; see [Ship gates & CI](/kapi/recipes/ship-gates-and-ci).

</TabItem>
