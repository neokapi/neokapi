# Reuse what you've translated

**Goal:** never re-translate a sentence you've already translated. When you ship an update, most text is unchanged — kapi brings back what it recognizes from earlier releases and sends only the new and changed parts forward, marking anything still untranslated so nothing slips out blank. Deterministic, seconds, no API key. Concepts: [Translation memory](/framework/translation-memory) and [Terminology](/framework/terminology); where each store lives: [TM & termbase storage](/kapi/recipes/tm-termbase-storage).

<Tabs groupId="surface" queryString>
<TabItem value="desktop" label="Desktop" default>

The **Translation Memories** view is the project TM's home:

1. **Import past work.** Import a TMX (or previous release's bilingual files) into the project TM; entries and language pairs are listed as they land.
2. **Run the flow.** A project flow whose first step is `recycle` fills every exact and fuzzy match from the TM before any translate step runs — **Bring up to date** applies it across locales, and only the misses go forward.
3. **Watch leverage accumulate.** Every finished run absorbs its results, so the next release starts warmer.

</TabItem>
<TabItem value="agent" label="Agent (Claude)">

Ask for the leverage pass:

> Import `project.tmx` into the project TM, pre-translate the French catalog from it, and tell me what's left.

The assistant runs `kapi tm import`, then `recycle`, and reports the residue — the blocks with no match — so you decide what goes to a model or a vendor. Approved sentence pairs it encounters along the way can be banked for the future with a `kind:"tm"` change-set entry through `kapi apply`.

</TabItem>
<TabItem value="cli" label="CLI">

Three deterministic steps — leverage, make the gaps visible, pre-flag terms:

```bash
kapi tm import project.tmx -s en -t fr        # 1. load past work (see tm stats)
kapi recycle messages_en.json -o step1.json \
  --source-lang en --target-lang fr           # 2. fill exact + fuzzy matches
kapi pseudo-translate step1.json -o step2.json  # 3. mark what the TM missed
kapi exec term-check step2.json --source-lang en --target-lang fr \
  --termbase product-terms                    # 4. pre-flag terminology drift
```

Tune matching with `--fuzzy-threshold` / `--fill-target-threshold` ([how matching works](/framework/translation-memory)). To machine-translate the misses instead of pseudo-filling them, swap step 3 for [`kapi translate`](/reference/commands/translate) and keep `term-check` as the guardrail.

**In a project**, declare it once as a flow and drop every flag:

```yaml title="my-app.kapi"
defaults:
  source_language: en
  target_languages: [fr]
flows:
  pretranslate:
    steps:
      - tool: recycle
      - tool: pseudo-translate
      - tool: term-check
```

`kapi run pretranslate` resolves the project TM, termbase, and languages automatically — and a `recycle` step at the head of the default flow gives [`kapi up`](/kapi/recipes/translate-content) the same leverage on every pass.

</TabItem>
