# Bulk rewrite with an agent

**Goal:** apply one editorial change everywhere (rename a product, retire a phrase, soften a tense) across files your editor can't even open (`.docx`, catalogs, HTML, Markdown), without risking structure. The division of labor: the agent decides what the new text says; kapi guarantees everything else: inline codes preserved, drift-guarded writes, and a check gate that proves the sweep is done. No second model is involved in the write.

<Tabs groupId="surface" queryString>
<TabItem value="desktop" label="Desktop" default>

The sweep itself is agent- or CLI-driven; Desktop is where you verify it:

1. **Before:** bind the rule that motivates the sweep (a forbidden term, a required phrasing) in the project's voice profile, so the **Checks** view shows exactly which blocks are affected and how many.
2. **After:** re-run the Checks view to confirm the count is zero, and spot-check the edited files in the preview: structure, styles, and placeholders intact.

For translated content, an edited source drops affected units back to *pending*; **Bring up to date** re-translates just those, and the [Review queue](/kapi/recipes/review-and-approve) picks up anything that parks.

</TabItem>
<TabItem value="agent" label="Agent (Claude)">

State the change once, over the whole set:

> We renamed "Acme Sync" to "Acme Flow". Update every mention across `docs/` and `src/locales/en/` (including the `.docx` one-pagers) and keep the formatting.

The assistant runs the loop at scale:

1. `kapi inspect --jsonl` over the set: one record per block, with its reference (`ref`), its revision (`rev`), and the text (inline codes as `<x id="…"/>` placeholders).
2. It rewrites only the blocks that mention the term, judgment calls included ("Acme Sync's engine" → "the Acme Flow engine"), which is why this is an agent job rather than a `sed` job.
3. `kapi apply` lands the change set. Each operation carries the revision it read, so a block someone changed since the read refuses the change set with its current text, and a concurrent edit can't be clobbered.
4. `kapi check --forbid "Acme Sync"` proves completion: exit 0 means the sweep is done.

Make the retired term a permanent [term](/kapi/recipes/keep-source-on-brand), and the old name can never quietly return. Recording a term is your decision, so the assistant suggests it and you keep it, or you add the `term` operation to the change set you apply.

</TabItem>
<TabItem value="cli" label="CLI">

The same loop with you (or a script) as the writer:

```bash
kapi inspect docs/**/*.md report.docx --jsonl > blocks.jsonl
# write a replace_text or set_content operation per matching block to
# edits.json, with the block's ref and rev; keep the <x id="…"/> tags
kapi apply edits.json --dry-run          # preview the whole sweep, one diff per document
kapi apply edits.json --in-place=.bak    # land it, keeping backups
kapi check docs/**/*.md --forbid "Acme Sync"   # prove it's done
```

For pure term substitution with zero judgment involved, `ksed -i 's/Acme Sync/Acme Flow/g'` or `kapi voice rewrite` does it deterministically: no agent, no model. The change set's shape and what refuses an edit are in [Edit content](/kapi/recipes/rewrite-content).
