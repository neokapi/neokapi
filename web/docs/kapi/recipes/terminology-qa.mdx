# Keep terms consistent

**Goal:** decide once how your key terms carry across languages — product names, UI actions, the words your domain depends on — and have kapi flag anything that drifts before it ships. The same termbase guides translation up front and validates it after. Concepts: [Terminology](/framework/terminology); storage models: [TM & termbase storage](/kapi/recipes/tm-termbase-storage).

The working artifact is a glossary your team already maintains, for example a CSV:

<TabItem value="desktop" label="Desktop" default>

The **Termbases** view is the glossary's home:

1. **Import the glossary.** Import the CSV into the project termbase; terms are listed by language pair and domain, ready to browse and search.
2. **Spot-check a term.** Look up an entry to confirm the approved target before a full pass.
3. **Enforce it.** With the termbase in the project, term findings surface in the **Checks** view, in the terminology gate of `check --ship`, and against each unit in the [Review queue](/kapi/recipes/review-and-approve) — the same drift, caught wherever you look.

</TabItem>
<TabItem value="agent" label="Agent (Claude)">

Ask for enforcement, or for curation:

> Check the French files against our glossary and fix what drifts.

The assistant looks up approved terms before it writes (`kapi termbase lookup`), runs `term-check` after, and fixes flagged targets through the round-trip. It can also grow the glossary: candidate terms it spots (or `kapi tool term-extract` surfaces) land as `kind:"term"` change-set entries through `kapi apply` — written to the committed glossary source, for you to approve in `git diff`.

</TabItem>
<TabItem value="cli" label="CLI">

Import once into a named termbase, verify, then check deliveries:

```bash
kapi termbase import glossary.csv --name product-terms \
  --format csv --header -s en -t fr                 # once; persists across sessions
kapi termbase lookup "log in" --name product-terms -s en -t fr
kapi term-check messages_fr.json \
  --source-lang en --target-lang fr --termbase product-terms
```

The `term-check` tool flags targets that don't use the approved equivalent for a source glossary term — "code secret" where the glossary says "mot de passe" — and exits non-zero on violations, so it doubles as a CI gate. Scale with globs and `-j 4`; keep the termbase current with re-imports (concepts merge) and `kapi termbase export` for vendor kits. Flags: [`kapi termbase`](/reference/commands/termbase), [`kapi tool term-check`](/reference/commands/tool-term-check).

**In a project**, the check resolves the project termbase and the recipe's languages automatically — no flags — and the terminology gate folds into [`kapi check --ship`](/kapi/recipes/gate-localization-in-ci).

</TabItem>
