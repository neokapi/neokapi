# Kapi

**Kapi** parses content in **any format**, lets you (or your AI agent) **edit and
check** the content inside it, and writes the original back **byte-for-byte** —
then makes that content work in **every language**. It is built on the open-source
[neokapi content engine](/framework/architecture).

Two jobs, one engine:

- **Keep your source content right** — edit it faithfully and verify it with
  **checks** for terminology, QA, and brand voice that act like **tests for AI
  output** (a draft scores 0–100 and a gate passes or fails).
- **Make it multilingual** — one verb, `kapi up`, reconciles the project toward
  its ship gates: translate with the AI you already have, reuse what you've
  translated, enforce your terminology, and park what needs a person for
  review — all without ever mangling the file's structure.

## Three ways to run it

Every surface works the same **engine, tools, flows, and
[`.kapi` projects](/reference/project-file)** — a workflow built in one runs in
the others:

- **Kapi Desktop** — a visual app: create projects, watch coverage against the
  ship gates, review and approve translations, build flows, manage plugins and
  credentials — no YAML, no flags.
- **Your AI assistant** — Claude (or any skill/MCP-capable tool) drives kapi by
  plain language, inside kapi's guardrails. See
  [Use with Claude](/kapi/get-started/use-with-claude).
- **Kapi CLI** — a single binary that operates directly on files. Best for
  automation, scripting, and CI.

Not sure which fits? See **[Kapi CLI or Kapi Desktop?](/kapi/get-started/cli-vs-desktop)**

## How you'll work

You drive Kapi either **ad-hoc** (one-off, on files you name) or as a **project**
(a `.kapi` recipe plus a store that remembers your work) — the same
commands, a different binding. See
**[Projects](/kapi/projects)**.

From there it's task by task: the [Kapi CLI recipes](/kapi/cli) walk preparing your
source and going multilingual, and [Kapi Desktop](/kapi/desktop/overview) does the
same work visually.
