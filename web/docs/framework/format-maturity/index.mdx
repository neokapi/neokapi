# Format support & maturity

neokapi reads and writes native document [formats](/framework/formats). The
**format-ops framework** measures each format's support against committed
evidence, publishes the results, and schedules maintenance as formats and
implementations change.

A deterministic scorer derives the maturity levels from that evidence. Repeated
runs over the same evidence produce the same levels.

## Two artifacts, kept separate

Each format has a maturity score and a published support tier.

- **The score** (a multi-axis vector) answers *how good support actually is*.
  It has one small ladder per axis, and it is recomputed by every audit
  from deterministic evidence in the format's own files. It ranks the remaining
  work and explains the tier; on its own it promises nothing.
- **The promise** (a support tier) answers *what you may rely on*. A format is
  **Supported** (a regression blocks a release), **Maintained** (tested and kept
  green), or **Available** (registered and usable, explicitly experimental). The
  tier changes only by an explicit, human-approved event, and it is backed by a
  CI gate that fails the build on a regression.

The headline tier is derived as the **minimum over the gating axes**, never an
average. This prevents a high score on one axis from hiding a weakness on
another gating axis. The vector explains and bounds the tier (a tier may never claim more
than its gating axes support), but the published tier moves only by a
human-approved promotion or demotion, and a tier claim is valid only while a CI
gate enforces it.

## Why it exists

Format readers and writers must preserve content and structure during edits
(see [Formats](/framework/formats)). Changes to an implementation or an upstream
specification can introduce regressions. Format-ops tracks the evidence needed
to detect them. Each format carries
committed evidence (its reader and writer, a specification, reference corpora,
and the tests that exercise them) and the audit computes a level per axis from
that evidence, not from opinion. When evidence is removed or becomes stale, the score
falls on the next run; when a gate stops running, the tier can no longer be
claimed. Scheduled maintenance keeps the measurement current with the code (see [Keeping it
alive](/framework/format-maturity/keeping-it-alive)).

## The live dashboard

The per-format scores, tiers, and trends are published on the live
[/format-maturity dashboard](/format-maturity), regenerated by the upkeep loop
rather than edited by hand. The set of formats it reports is derived from the
real format directories in the build; there is no list to maintain and no count
to hardcode.
